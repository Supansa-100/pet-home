## 1. วัตถุประสงค์ของระบบ (System Purpose)

**PET-HOME** คือ Web Application ที่ทำหน้าที่เป็น **สื่อกลาง** ระหว่างสองกลุ่มหลัก:

| กลุ่ม | ความต้องการ |
|---|---|
| **เจ้าของสัตว์เลี้ยง** | ต้องการหาบ้านและผู้อุปการะที่เหมาะสมให้สัตว์เลี้ยง แต่ขาดระบบคัดกรองผู้รับ |
| **ผู้ต้องการรับอุปการะ** | ต้องการหาสัตว์เลี้ยงตรงความต้องการ แต่ข้อมูลกระจัดกระจาย ขาดมาตรฐาน |

**ปัญหาที่ระบบแก้ไข:**
- ❌ เจ้าของไม่มีเครื่องมือคัดกรองผู้รับอุปการะ
- ❌ ผู้รับอุปการะหาสัตว์ที่ตรงความต้องการได้ยาก
- ❌ โพสต์ประกาศทั่วไปขาดการดูแลความเหมาะสม

**สิ่งที่ระบบจัดเตรียม:**
- ✅ แพลตฟอร์มลงประกาศมาตรฐานพร้อมรูปภาพและรายละเอียดครบถ้วน
- ✅ ระบบค้นหา/กรองสัตว์เลี้ยงตามเงื่อนไขที่ต้องการ
- ✅ Workflow คำขอรับอุปการะพร้อมระบบติดตามสถานะ
- ✅ Admin Dashboard สำหรับดูแลความเหมาะสมและความปลอดภัย

## 2. กลุ่มผู้ใช้งานหลัก (Actors)

ระบบ PET-HOME มีผู้ใช้งาน **3 บทบาท (Roles)** ดังนี้:

---

### 👤 Role 1 — เจ้าของสัตว์เลี้ยง (Pet Owner / Poster)

ผู้ที่ต้องการหาบ้านใหม่ให้สัตว์เลี้ยงของตนเอง

**ความสามารถหลัก:**
- ลงประกาศสัตว์เลี้ยงพร้อมรูปภาพและรายละเอียดครบถ้วน
- แก้ไขหรือปิดประกาศเมื่อสัตว์ได้บ้านแล้ว
- ดูและพิจารณาคำขอรับอุปการะที่เข้ามา (อนุมัติ / ปฏิเสธ)
- สื่อสารกับผู้ที่ต้องการรับเลี้ยงผ่านระบบ

**ข้อมูลที่ระบุในประกาศ:** รูปภาพ, ชนิดสัตว์, สายพันธุ์, อายุ, เพศ, ขนาด, สี, ประวัติสุขภาพ/วัคซีน, เงื่อนไขการรับเลี้ยง, พื้นที่/จังหวัด

---

### 🐾 Role 2 — ผู้ต้องการรับอุปการะ (Adopter)

ผู้ที่มองหาสัตว์เลี้ยงเพื่อนำไปดูแล

**ความสามารถหลัก:**
- ค้นหาและกรองสัตว์เลี้ยงตามเงื่อนไขที่ต้องการ (ชนิด, สายพันธุ์, ขนาด, เพศ, พื้นที่)
- อ่านรายละเอียดและเงื่อนไขของเจ้าของจากหน้าประกาศ
- ส่งคำขอรับอุปการะพร้อมข้อความแนะนำตัว
- ติดตามสถานะคำขอของตนเอง
- ยกเลิกคำขอที่ยังรอพิจารณา

---

### 🛡️ Role 3 — ผู้ดูแลระบบ (Administrator / Admin)

ผู้ที่มีสิทธิ์สูงสุดในการดูแลและควบคุมแพลตฟอร์ม

**ความสามารถหลัก:**
- จัดการบัญชีผู้ใช้งาน (แบน / ปลดแบน)
- ตรวจสอบและซ่อน/ลบประกาศที่ไม่เหมาะสม
- จัดการหมวดหมู่สัตว์เลี้ยง
- ดูภาพรวมสถิติของระบบผ่าน Dashboard

## 4. กระบวนการหลักของระบบ (Main Workflows)

### 4.1 กระบวนการลงประกาศ (Posting Workflow)

```
[Pet Owner] -> สมัครสมาชิก/เข้าสู่ระบบ
           -> สร้างประกาศ (กรอกข้อมูล + อัปโหลดรูป)
           -> ประกาศปรากฏในระบบ (status: available)
           -> [Admin] ตรวจสอบความเหมาะสม
               +-- เหมาะสม -> ประกาศแสดงต่อไป
               +-- ไม่เหมาะสม -> ซ่อน/ลบประกาศ
```

### 4.2 กระบวนการรับอุปการะ (Adoption Workflow)

```
[Adopter] -> ค้นหา/กรองสัตว์เลี้ยง
          -> อ่านรายละเอียดประกาศ
          -> ส่งคำขอรับอุปการะ + ข้อความแนะนำตัว (status: pending)
          -> [Pet Owner] รับการแจ้งเตือน -> ดูรายการคำขอ
               +-- อนุมัติ -> listing status -> adopted
               |             คำขออื่น (pending) -> rejected อัตโนมัติ
               |             [Adopter] ได้รับแจ้ง: อนุมัติแล้ว
               +-- ปฏิเสธ -> status: rejected
                             [Adopter] ได้รับแจ้ง: ถูกปฏิเสธ
```

### 4.3 กระบวนการดูแลระบบ (Admin Workflow)

```
[Admin] -> เข้าสู่ Admin Dashboard
        -> ตรวจสอบสถิติภาพรวม
        -> จัดการผู้ใช้ (ดู/แบน/ปลดแบน)
        -> ตรวจสอบประกาศ (ดู/ซ่อน/ลบ)
        -> จัดการหมวดหมู่สัตว์เลี้ยง
```

### 4.4 กระบวนการสนทนาแชท (Chat Workflow)

```
[Adopter] -> ส่งคำขอรับอุปการะ (Adoption Request)
          -> ระบบสร้าง Chat Room โดยอัตโนมัติ (1 Request = 1 Room)
          -> ทั้งสองฝ่ายเห็นห้องแชทใน "กล่องข้อความของฉัน"
          -> สนทนพูดคุยแลกเปลี่ยนข้อมูลเพิ่มเติม
[Pet Owner] -> พิจารณาแล้ว อนุมัติ / ปฏิเสธคำขอผ่านหน้า Request
             -> ห้องแชทยังเปิดอยู่หลังตัดสินใจ (อ่านประวัติย้อนหลังได้)
```

## 5. สถานะของข้อมูลสำคัญ (Status States)

### สถานะประกาศ (Pet Listing Status)

```
available --(มีคนส่งคำขอ)--> pending
    |                              |
    |                    (อนุมัติคำขอ)
    |                              |
    +--(เจ้าของปิดเอง)--> closed   v
                               adopted
```

| สถานะ | ความหมาย | การแสดงผล |
|---|---|---|
| `available` | เปิดรับคำขออยู่ | แสดงในรายการ, ส่งคำขอได้ |
| `pending` | มีคำขอรอพิจารณา | แสดงในรายการ, ส่งคำขอไม่ได้ |
| `adopted` | ได้รับการอุปการะแล้ว | อาจแสดงหรือซ่อน |
| `closed` | เจ้าของปิดประกาศเอง | ไม่แสดงในรายการ |

### สถานะคำขอรับอุปการะ (Adoption Request Status)

| สถานะ | ความหมาย |
|---|---|
| `pending` | รอเจ้าของพิจารณา |
| `approved` | เจ้าของอนุมัติแล้ว |
| `rejected` | เจ้าของปฏิเสธ / ถูก reject อัตโนมัติ |
| `cancelled` | Adopter ยกเลิกเอง |

### สถานะห้องแชท (Chat Room Status)

> ห้องแชทไม่มี status ซับซ้อน — อยู่ในสถานะ **active** ตลอดเวลา แม้ Request จะถูก approved/rejected/cancelled แล้วก็ยังอ่านประวัติย้อนหลังได้

## 6. Tech Stack ที่ใช้ในระบบ

| Layer | Technology | หมายเหตุ |
|---|---|---|
| **Frontend** | React 18 + Vite 5 + CSS | SPA, Hot Reload dev |
| **Backend** | Node.js 20 LTS + Express 4 | REST API |
| **Database** | MySQL 8 | utf8mb4, InnoDB |
| **Dev Tools** | Docker Compose + phpMyAdmin | Local Dev Environment |
| **Production** | Railway (single container, multi-stage Dockerfile) | ไม่มี Nginx แยก |

## 8. Port Mapping (Development Environment)

| Service | Host Port | Container Port | หมายเหตุ |
|---|---|---|---|
| Frontend (Vite) | `5173` | `5173` | Hot Reload |
| Backend (Express) | `5001` | `5001` | nodemon (`-L` บน Windows) |
| MySQL 8 | `3307` | `3306` | healthcheck required |
| phpMyAdmin | `8081` | `80` | Apple Silicon -> `platform: linux/amd64` |

> **หมายเหตุ:** ไม่ใช้ Port `5000` เพื่อป้องกันการชนกับ macOS AirPlay

## 9. ข้อกำหนดที่ไม่ใช่ Functional (Non-Functional Requirements Overview)

| ด้าน | ข้อกำหนด |
|---|---|
| **ความปลอดภัย** | JWT Auth, bcrypt password hashing, Role-based access control (RBAC), CORS, Helmet.js |
| **ความสามารถขยาย** | Connection pool ฐานข้อมูล, Pagination ทุก list endpoint |
| **ไฟล์/รูปภาพ** | จำกัดสูงสุด 5 รูปต่อประกาศ, ขนาดสูงสุด 5MB/รูป, รองรับ JPG, JPEG, PNG, WEBP |
| **ความพร้อมใช้** | Dev: Docker Compose / Prod: Railway (managed uptime) |
| **การจัดการข้อผิดพลาด** | Global error handler, 404 handler, Friendly error messages |
| **UX** | Responsive design (Mobile-friendly), Loading skeleton, Toast notifications |
| **ตัวอักษร** | Database charset `utf8mb4` (รองรับภาษาไทยและ Emoji) |
