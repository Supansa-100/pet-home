# AI Working Rules

กฎและข้อกำหนดการทำงานร่วมกับ AI สำหรับโปรเจกต์ PET-HOME เพื่อให้การพัฒนาเป็นไปอย่างมีระบบและลดข้อผิดพลาด

## 1. การทำงานตาม Phase อย่างเคร่งครัด
- AI จะต้องรับทราบและดำเนินงานตาม **Phase (0-7)** ที่ระบุในเอกสาร `imprementtation.md` เท่านั้น
- ห้าม AI ข้ามไปเขียนโค้ดของ Phase ถัดไปหาก Phase ปัจจุบันยังไม่เสร็จสมบูรณ์หรือยังไม่ได้รับการ Approve จากผู้พัฒนา

## 2. Planning ก่อน Execution เสมอ
- ก่อนจะเริ่มเขียนโค้ดสำหรับแต่ละ Phase AI จะต้องอ่านเป้าหมายและ Acceptance Criteria ก่อน
- AI จะต้องพิมพ์สรุปแผนงาน (Implementation Plan) ให้ผู้พัฒนาตรวจสอบและอนุญาตก่อนที่จะใช้ Tool พิมพ์คำสั่งสร้าง/แก้ไขไฟล์

## 3. การใช้คำสั่งใน Terminal
- การใช้เครื่องมือ เช่น `docker-compose`, `npm install` หรือ `node` ให้ดำเนินการหลังจากแจ้งผู้พัฒนาแล้ว หรือขออนุญาตกด Run ก่อน
- ห้ามรันคำสั่งทำลายล้างหรือลบฐานข้อมูล (`docker-compose down -v`) โดยไม่แจ้งเตือนผู้ใช้อย่างชัดเจนล่วงหน้า

## 4. ปัญหาแฝงทางเทคนิค (Known Quirks)
- **Port 5000**: ห้ามใช้สำหรับ Backend เนื่องจากชนกับพอร์ตระบบ (AirPlay) ในเครื่อง Mac บางรุ่น ให้เปลี่ยนเป็น `5001`
- **Docker + Nodemon บน Windows**: หากมีการแก้ไขไฟล์ใน backend แล้ว nodemon ไม่มีการโหลดใหม่ ให้ตรวจสอบ package.json ว่ามี flag `-L` (Legacy Watch) ในคำสั่ง dev หรือไม่
- **Reverse Proxy**: ห้ามเสียเวลาตั้งค่า Nginx สำหรับโปรเจกต์นี้ เนื่องจากเงื่อนไข Deployment บังคับใช้ Railway (Railway จัดการ SSL และ Reverse Proxy ให้อยู่แล้ว)

## 5. การขอความช่วยเหลือเมื่อเจอข้อผิดพลาด
- เมื่อรันคำสั่งแล้วมี Error เกิดขึ้น ให้ AI วิเคราะห์ Error Log ค้นหาสาเหตุ แล้วพิมพ์แนวทางแก้ไข ก่อนที่จะรันคำสั่งแก้ไขแบบอัตโนมัติ
