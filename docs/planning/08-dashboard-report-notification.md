# Dashboard, Report & Notification Design - PET-HOME

เอกสารนี้รวบรวมการออกแบบ Dashboard, Reports, Notifications และ SLA Alerts สำหรับระบบ PET-HOME เพื่อตอบโจทย์ความต้องการของกลุ่มผู้ใช้งานแต่ละประเภท โดยอิงจากข้อมูล Database และ Workflow ที่ได้วางแผนไว้

---

## 1. Dashboard Design (การแสดงผลแบ่งตามกลุ่มผู้ใช้งาน)

### 1.1 สำหรับผู้เข้าชมทั่วไป (Public / Guest)
**เป้าหมาย:** สร้างความน่าเชื่อถือ แสดงความเคลื่อนไหว และเชิญชวนให้เข้าร่วม (Call to Action)
*   **Dashboard Cards (Success Metrics):**
    *   `สัตว์เลี้ยงที่ได้บ้านใหม่แล้ว`: ตัวเลขแสดงจำนวนสถิติความสำเร็จ (สะท้อนความน่าเชื่อถือ)
    *   `สัตว์เลี้ยงที่กำลังรอบ้าน`: จำนวนโพสต์ที่ยังมีสถานะ Available (สะท้อนขนาดของแพลตฟอร์ม)
*   **Tables / Grids (Discovery & Relevance):**
    *   `เพื่อนตัวน้อยมาใหม่`: แสดงการ์ดสัตว์เลี้ยงที่เพิ่งโพสต์ล่าสุด 6-8 ตัว (เรียงตาม `createdAt` DESC)
    *   `สัตว์เลี้ยงใกล้คุณ`: (หากผู้ใช้อนุญาตให้เข้าถึงตำแหน่ง หรือเลือกตัวกรองจังหวัด) แสดงการ์ดสัตว์เลี้ยงในพื้นที่
*   **Call to Action:** ปุ่มขนาดใหญ่ "ดูน้องๆ ทั้งหมด" และ "ลงประกาศหาบ้าน"
*   *ตัวอย่างข้อมูลที่ใช้คำนวณ:*
    *   *Total Adopted:* `SELECT COUNT(*) FROM pets WHERE status = 'ADOPTED'`

### 1.2 เจ้าของสัตว์เลี้ยง (Pet Owner)
**เป้าหมาย:** หาบ้านได้ไว คัดกรองคนได้ และไม่พลาดทุกการติดต่อ
*   **Dashboard Cards:**
    *   `ประกาศของฉันที่ยัง Active`: จำนวนประกาศสถานะ AVAILABLE
    *   `คำขออุปการะที่รอการพิจารณา`: จำนวน Requests สถานะ PENDING (ต้องการ Action จากเจ้าของ)
    *   `ข้อความแชทใหม่`: จำนวนแชทที่ Unread (เพื่อการตอบกลับที่รวดเร็ว)
 *   **Tables:**
    *   `คำขอรับอุปการะล่าสุด`: ตารางแสดง (ผู้ส่งคำขอ | ชื่อสัตว์ | วันที่ | สถานะ | [ปุ่มดูรายละเอียด/แชท])
*   **Filters:** ตัวกรองตารางตามสถานะ (รอพิจารณา, คุยอยู่, อนุมัติแล้ว)
*   *ตัวอย่างข้อมูลที่ใช้คำนวณ:*
    *   *Pending Requests:* `COUNT(requests) WHERE pet.ownerId = userId AND request.status = 'PENDING'`

### 1.3 ผู้ต้องการรับอุปการะ (Adopter)
**เป้าหมาย:** ติดตามสถานะคำขอได้อย่างชัดเจน และรู้ว่าความหวังยังมีหรือไม่
*   **Dashboard Cards:**
    *   `คำขอที่กำลังรอเจ้าของตัดสินใจ`: (Pending Requests)
    *   `คำขอที่ผ่านการอนุมัติ`: (Approved Requests)
    *   `ข้อความแชทใหม่`: แจ้งเตือนเมื่อเจ้าของทักกลับหรือขอรายละเอียดเพิ่ม
*   **Tables:**
    *   `ประวัติการส่งคำขอ`: ตารางแสดง (ชื่อสัตว์ | สถานะสัตว์ปัจจุบัน | สถานะคำขอเรา | [ปุ่มแชท])
        *(ข้อสำคัญ: หากสัตว์ตัวนั้นถูก Owner อนุมัติให้คนอื่นไปแล้ว สถานะสัตว์จะเปลี่ยนเป็น 'ADOPTED' ระบบต้องแสดงให้ Adopter คนนี้รู้ว่าน้องได้บ้านไปแล้ว)*
*   *ตัวอย่างข้อมูลที่ใช้คำนวณ:*
    *   *Pet Current Status:* ตรวจสอบ `Pet.status` จาก `petId` ที่เชื่อมกับ Request เพื่อแสดงผลให้ Adopter ทราบ

### 1.4 ผู้ดูแลระบบ (Admin)
**เป้าหมาย:** เห็นภาพรวม, ตรวจสอบความปลอดภัย, ประเมินการเติบโต และจัดการจุดที่มีปัญหา
*   **Dashboard Cards:**
    *   `จำนวนผู้ใช้งานทั้งหมด (Total Users)`
    *   `อัตราการจับคู่สำเร็จ (Match Success Rate)`
    *   `จำนวนเคสที่ถูกแจ้งรายงาน (Pending Reports)` (ต้องการ Action จาก Admin ด่วน)
    *   `จำนวนประกาศใหม่ในวันนี้ (Daily New Listings)`
*   **Charts:**
    *   `Traffic Chart (Line Graph)`: เปรียบเทียบยอดลงประกาศใหม่ vs ยอดจับคู่สำเร็จ ย้อนหลัง 30 วัน
    *   `Categories Chart (Pie Chart)`: สัดส่วนชนิดสัตว์ (เช่น หมา 60%, แมว 35%, นก 5%)
*   **Tables:**
    *   `Reported Posts`: รายการโพสต์ที่ผู้ใช้กด "รายงานเนื้อหา" (ชื่อโพสต์ | เหตุผล | จำนวนผู้รายงาน | [ปุ่มตรวจสอบ/ลบ])
*   **Filters:** ตัวกรอง Dashboard แบบ Global (เช่น ข้อมูลวันนี้, 7 วัน, 1 เดือน, ทั้งหมด)

## 2. Report Export (การส่งออกรายงานสำหรับ Admin)
สำหรับโหลดข้อมูลไปวิเคราะห์ต่อภายนอก (Format: `.CSV`, `.XLSX`)
1.  **User Growth Report:** สถิติการสมัครสมาชิกใหม่ แยกรายวัน/สัปดาห์
2.  **Adoption Success Metrics:** รายชื่อสัตว์ที่ได้บ้าน พร้อมวัด `Time-to-Adopt` (ระยะเวลาเฉลี่ยตั้งแต่เริ่มโพสต์จนถึงวันที่ถูกปรับสถานะเป็น ADOPTED)
3.  **Audit & Moderation Report:** บันทึกการจัดการของ Admin (การระงับบัญชี, ลบโพสต์, ซ่อนโพสต์ผิดกฎ)

## 3. Notification Rules (กฎการแจ้งเตือน)
ส่งผ่านระบบ In-App Notification (กระดิ่ง) และอัปเดตแบบ Real-time
*   **Pet Owner Events:**
    *   เมื่อมีคนส่งคำขอรับอุปการะใหม่ `["มีผู้สนใจรับอุปการะ (ชื่อสัตว์) กดเพื่อดูโปรไฟล์"]`
    *   เมื่อได้รับข้อความแชทใหม่
*   **Adopter Events:**
    *   เมื่อเจ้าของตอบรับ/อนุมัติคำขอ `["ยินดีด้วย! คำขอรับอุปการะ (ชื่อสัตว์) ได้รับการอนุมัติแล้ว"]`
    *   เมื่อเจ้าของปฏิเสธคำขอ `["ขออภัย คำขอรับอุปการะ (ชื่อสัตว์) ไม่ผ่านการพิจารณา"]`
    *   เมื่อสัตว์ที่ตนเองยื่นคำขอไป ถูกคนอื่นรับอุปการะแล้ว `["(ชื่อสัตว์) ได้บ้านใหม่แล้ว ขอบคุณที่ให้ความสนใจ"]`
    *   เมื่อได้รับข้อความแชทใหม่
*   **Admin Events:**
    *   เมื่อโพสต์ใดโพสต์หนึ่งถูกผู้ใช้ Report ครบ 3 ครั้ง (เพื่อให้เข้ามาตรวจสอบความปลอดภัย)

## 4. SLA Alert Rules (กฎกระตุ้นการเคลื่อนไหว)
ระบบแจ้งเตือนเชิงรุก (Proactive Alerts) เพื่อป้องกันไม่ให้แพลตฟอร์มมีข้อมูลเก่าค้าง หรือทำให้ผู้ใช้รู้สึกว่าระบบร้าง
*   **Rule 1: คำขอที่ถูกละเลย (Pending Request Timeout)**
    *   *เงื่อนไข:* คำขอรับอุปการะอยู่ในสถานะ `PENDING` เกิน 5 วัน (ไม่มีการอนุมัติ/ปฏิเสธ หรือแชท)
    *   *Action:* แจ้งเตือน Owner -> `"คุณมีคำขอรับอุปการะที่รอพิจารณาอยู่ โปรดตอบกลับเพื่อไม่ให้ผู้รับเลี้ยงรอนาน"`
*   **Rule 2: ประกาศเก่า (Stale Listing Alert)**
    *   *เงื่อนไข:* ประกาศสัตว์เลี้ยงที่สถานะ `AVAILABLE` และไม่มีการอัปเดต หรือไม่มีความเคลื่อนไหวใดๆ เกิน 30 วัน
    *   *Action:* แจ้งเตือน Owner -> `"ประกาศของ (ชื่อสัตว์) ยังหาบ้านอยู่หรือไม่? หากได้บ้านแล้วโปรดอัปเดตสถานะ หรืออัปเดตรูปใหม่เพื่อเพิ่มความน่าสนใจ"`
*   **Rule 3: ข้อความที่ไม่ได้อ่าน (Unread Messages Escalation)**
    *   *เงื่อนไข:* มีข้อความแชทที่ถูกทิ้งไว้ในสถานะ Unread เกิน 48 ชั่วโมง
    *   *Action:* ส่ง Email แจ้งเตือน (Email Notification) -> `"คุณมีข้อความใหม่เกี่ยวกับสัตว์เลี้ยงที่ยังไม่ได้อ่านบน PET-HOME"` (ใช้ Email เมื่อผู้ใช้ไม่ได้เข้าแอป)
